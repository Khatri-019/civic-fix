## 1. Why this design (and what to watch out for)

| Goal | How this plan meets it |
|---|---|
| Realistic inputs | Real photos plus real voices, instead of only synthetic one-liners |
| Labels you can trust | Gemini *proposes* category/severity; **members verify**. The test set is 100% human-verified and **double-checked by a second member**. |
| Fair Gemini vs DistilBERT comparison | Gemini drafts the labels, so the test labels must be human-checked or the comparison is circular |
| No train/test leakage | Several texts are written per photo, so the split is **by photo**: all texts of one photo go to the same split |
| Works with existing code | Final CSVs keep the plan's columns `raw_complaint, category, severity, has_contradiction` (see the "Real Data Swap Guide" in the build plan) |

**Know what each model actually uses:**
- **DistilBERT (Phase 7)** is trained on **text only**. Photos don't train it directly; they make the texts realistic and varied.
- **Gemini (Phase 4 pipeline)** uses text + image + transcript. Photos and voices matter most for **evaluation** (modality ablation, contradiction detection).
- **MiniLM NLI (Phase 7)** is pre-trained. It needs **claim vs. evidence pairs** for evaluation, which this dataset provides.

## 2. Target size

Categories are fixed by `config.py` (11). Severities: Low / Medium / High / Critical.

| Item | Total (minimum) | Total (recommended) | **Per member (recommended)** |
|---|---|---|---|
| Photos | 66 | 130–160 | **~35–40** (≈12–15 per category; fewer for Transport / Internet / Other) |
| Complaint texts (4 per photo + text-only rows) | ~300 | ~650 | generated by 🤖; each member reviews ~160 |
| Contradiction examples | ≥ 60 | ≥ 130 | generated by 🤖 (1 per photo) |
| Voice clips | 40 (10 each) | 80–100 | **20–25 clips** |
| Human-verified test set | 60 texts | 120 texts | ~30 each + F2's cross-check |

**Balance rules** (DistilBERT's stratified split crashes or performs badly otherwise):
- Every category: **≥ 20 texts** in total.
- Every severity: **≥ 40 texts** in total. **Critical** is the rare one: **each member should find at least 4 clearly High/Critical photos.**
- No single category above ~15% of the data.

## 4. Step 1 — Collect photos 👥 (all members in parallel)

### 4.1 Where to get them (in order of preference)
1. **Your own phone photos** of your campus, hostel or neighbourhood. Best fit for the "college/hostel" setting, and no licence issues.
2. **Free-licence photo sites:** Wikimedia Commons (CC0 / CC-BY), Unsplash, Pexels. Search e.g. "broken streetlight", "overflowing garbage bin", "water leak ceiling", "pothole road".
3. **Public research datasets** (take a handful of images, don't bulk-copy):
   - **TACO** (litter in context): Waste Management / Cleaning
   - **RDD2022** (road damage, includes Indian roads): Infrastructure
   - Kaggle "pothole", "garbage classification" and "water leakage" datasets

   Check each dataset's licence page before use.

**Don't** scrape Google Images or news sites: licences are unknown and you can't cite them in a report.

### 4.2 Photo rules (same for everyone)
- Format `.jpg` / `.png`, ideally ≥ 640 px on the short side. Phone resolution is fine.
- **One clear problem per photo**, recognisable without explanation.
- **Privacy:** no identifiable faces, licence plates, ID cards, room-number name tags. Crop or blur them first. Photos are sent to Gemini, and Google's free tier may use them to improve its products.
- Mix of conditions: day and night, close-up and wide, indoor and outdoor.
- **Severity spread:** for each category, some minor problems *and* some serious ones.
- Name files `<prefix>_<NNN>.jpg`, numbered from 001 within each category:

| prefix | category | owner |
|---|---|---|
| `el` | Electrical | M1 |
| `se` | Security | M1 |
| `tr` | Transport | M1 |
| `in` | Infrastructure | M2 |
| `pw` | Plumbing / Water | M2 |
| `nw` | Internet / Network | M2 |
| `wm` | Waste Management | F1 |
| `sn` | Sanitation | F1 |
| `ot` | Other | F1 |
| `ch` | Cleaning / Housekeeping | F2 |
| `ff` | Furniture / Facilities | F2 |

- For every photo you didn't take yourself, add a line to `images/<category_folder>/SOURCES.txt`: `<filename> | <source URL> | <licence>`.

### 4.3 Shot list ideas per category

| Category (owner) | Low / Medium examples | High / Critical examples |
|---|---|---|
| Electrical (M1) | flickering tube, broken switch plate | dark street with dead lamp, **exposed live wires**, sparking socket, burnt board |
| Security (M1) | broken lock | broken boundary wall/gate, **broken CCTV**, unlit entrance |
| Transport (M1) | faded bus stop sign | damaged bus shelter; *"bus didn't come" → text-only* |
| Infrastructure (M2) | cracked tile, peeling plaster | **pothole on road**, broken stairs, collapsed wall section |
| Plumbing / Water (M2) | dripping tap, small leak stain | burst pipe, flooded floor, **sewage overflow** |
| Internet / Network (M2) | router with red light, loose LAN cable | *hard to photograph → mostly text-only rows* |
| Waste Management (F1) | small litter pile | overflowing bin, garbage dump with animals |
| Sanitation (F1) | dirty washbasin | clogged/overflowing toilet, open drain |
| Other (F1) | anything that fits nowhere else | stray-animal hazard, tree fallen on path |
| Cleaning / Housekeeping (F2) | dusty corridor, unswept stairs | heavy dirt in a mess area, pest droppings |
| Furniture / Facilities (F2) | broken chair, wobbly desk | broken ceiling fan hanging, damaged railing |

### 4.4 Done when (each member checks their own)
- [ ] Photos uploaded to the shared `images/<category_folder>/`, named correctly
- [ ] Every owned category has ≥ 6 photos (Transport, Internet / Network, Other may have fewer)
- [ ] ≥ 4 of your photos are clearly **High/Critical**
- [ ] `SOURCES.txt` filled for every downloaded photo

## 5. Step 2 — Image manifest + label review 🤖 → 👥

**🤖 Claude builds** `tools/build_image_manifest.py`, which the lead runs. It:
1. Scans `data/real/images/` and builds `manifests/images.csv` (with an `owner` column from the folder → owner map above).
2. Sends each photo to Gemini once and gets a **neutral English scene description**, a **proposed severity** and a **sanity-check category** (flags photos whose folder disagrees).
3. Caches every response, so re-runs never re-bill a photo.
4. Writes **one review sheet per member**: `review/images_M1.csv`, `images_M2.csv`, `images_F1.csv`, `images_F2.csv`.

Sheet columns:

| column | filled by | example |
|---|---|---|
| `image_id` | 🤖 | `el_003` |
| `file` | 🤖 | `images/electrical/el_003.jpg` |
| `category` | 🤖 from folder | `Electrical` |
| `gemini_category_check` | 🤖 | `Electrical` (flagged if different) |
| `scene_description` | 🤖 | "Street lamp at night, unlit; road dark." |
| `severity_proposed` | 🤖 | `High` |
| `severity` | **👥 owner confirms/edits** | `High` |
| `source` / `license` | 🤖 from `SOURCES.txt`, else `own` | `own` |
| `verified` | **👥 owner** | `yes` |

**👥 Each member** opens their own sheet, fixes `severity`, sets `verified=yes`, and saves it back to the shared `review/` folder. **👤 The lead** copies the sheets back. The next 🤖 step merges them into `images.csv` and refuses to continue while any row is unverified.

Severity definitions (from `src/prompts.py`), which **everyone must use the same way**:
- **Low:** minor inconvenience, no safety impact.
- **Medium:** meaningful inconvenience, needs maintenance, not urgent.
- **High:** significant impact on safety, accessibility, sanitation or essential services.
- **Critical:** immediate danger needing urgent response.

> Tip: before Step 2, do a 10-minute **calibration**. All 4 members label the same 8 photos independently, compare, and agree on borderline cases. This keeps severity consistent across people.

## 6. Step 3 — Generate English complaint texts per photo 🤖

**🤖 Claude builds** `tools/generate_complaints.py`, which the lead runs. For each verified photo, **one Gemini call** returns 4 English complaint variants written as students/residents would type them:

| variant | style | `has_contradiction` | example (for a dead streetlight photo) |
|---|---|---|---|
| `consistent_informal` | short, casual English: abbreviations, lowercase, small typos | false | "light outside main gate not working since 3 days, v dark at night" |
| `consistent_detailed` | fuller, well-written English; adds plausible location/duration | false | "The streetlight outside the main gate hasn't worked since Monday and the road is completely dark after 7 pm." |
| `vague` | minimal info | false | "light not working" |
| `contradicting` | claim the photo **contradicts** (exaggeration, wrong object, wrong scale) | **true** | "all the lights on campus are sparking and on fire" |

**Text-only rows:** for categories that are hard to photograph (Internet / Network, Transport, some Security / Other), the script also generates English text-only complaints from a category + severity seed. Their `image_id` is empty, and they're assigned to the category owner for review.

Rules baked into the prompt:
- **English only.** Informal English (Indian-English phrasing such as "since 3 days" is fine), but no Hindi/Hinglish words.
- Category and severity are **inherited from the verified photo labels**, not invented by Gemini.
- The contradicting variant must conflict with what's visible, not just add unverifiable detail. Unverifiable details (e.g. "since 3 days") are fine in consistent variants.
- Vary length (3–40 words).

Output: `manifests/complaints_draft.csv` (`record_id, image_id, owner, variant, raw_complaint, category, severity, has_contradiction, split, label_source=gemini_draft`). The script also pre-assigns `split` (about 20% of photos → `test`, grouped by photo, stratified), so reviewers know which rows matter most.

**Cost:** 1 call per photo + 1 per 10 text-only rows, so ~150–200 calls for the recommended size. The script throttles itself and resumes where it stopped if a quota error hits.

## 7. Step 4 — Review texts 👥 (parallel, with cross-check on the test set)

**🤖 Claude** splits the draft into `review/texts_M1.csv` … `texts_F2.csv` (rows for each owner's categories).

**👥 Each member** checks their own sheet:
- [ ] Does the text sound like a real person complaining in English? Delete or fix robotic ones.
- [ ] Is the `category` right *for the text*? Text and photo can differ subtly, e.g. "smell" pushes toward Sanitation.
- [ ] Is the `severity` right *for the text*? A vague text about a serious photo may still be High.
- [ ] Does the `contradicting` variant truly contradict the photo?
- [ ] Set `label_source=human_verified` on rows you checked.

**Minimum per member:** **every `split=test` row** (~30) plus a random 20% of your training rows. Expect about 1 minute per 3–4 rows, so about 45–60 min per member.

**Cross-check (F2, plus anyone free):** 🤖 builds `review/test_crosscheck.csv` with all test rows from M1, M2 and F1 *without their labels*. F2 labels category, severity and contradiction independently. F2's own test rows go to M1 the same way. 🤖 then reports **inter-annotator agreement** (Cohen's κ), a strong number to cite in the report. Disagreements are settled by a quick discussion, and the final label is written to the test row.

## 8. Step 5 — Voice recordings 👥 (each member records themselves)

### 8.1 Consent first
Voice is personal data, even within the team. Each member signs a short consent (a template is in `data/real/consent/README.md`, which Claude will create) covering:
- what it's used for: local speech-to-text and the project report;
- that audio is transcribed **locally with Whisper**: the audio itself is **not** sent to Gemini, only the text transcript;
- that raw audio won't be published without permission, and can be deleted on request.

### 8.2 What each member reads
**🤖 Claude generates** `data/real/scripts/<ID>.md`, 20–25 English lines per member, with:
- **Overlap:** about 10 lines recorded by **all 4 members**. This lets us compare Whisper accuracy across speakers and male vs female voices.
- **Lines from other members' categories,** so each speaker covers every category and every severity, plus some `contradicting` lines.
- Each line has its `record_id`, e.g. `[pw_004_informal]`.

### 8.3 How to record
- **Device:** any phone voice recorder. Save as `.m4a`, `.mp3` or `.wav` (all supported).
- **Length:** 5–25 seconds per clip. **One complaint per file.**
- **Read naturally**, as if complaining to a warden. Small deviations from the script are fine; keep them.
- **Environment:** about 70% quiet room, about 30% realistic noise (corridor, fan, outdoors). Note which in the filename.
- **Bonus (optional):** 3–5 clips each **in your own words** (not reading), with the suffix `_free`. These test real spontaneous speech.
- **Filename:** `<ID>_<record_id>_<env>.m4a`, where `env` = `quiet` or `noisy`.
  Examples: `F1_pw_004_informal_quiet.m4a`, `M2_tr_t03_vague_noisy.m4a`, `M1_el_003_free_quiet.m4a`.
- Upload to the shared `audio/<ID>/` folder.

### 8.4 Done when (each member)
- [ ] Consent signed and uploaded to the shared `consent/` folder (restricted)
- [ ] ≥ 10 clips (recommended 20–25), named correctly
- [ ] All shared lines recorded

## 9. Step 6 — Audio processing 🤖 (lead runs)

**🤖 Claude builds** `tools/process_audio.py`. It:
1. Parses filenames → `speaker`, `gender`, `record_id`, `env`.
2. Transcribes each clip with the existing `src/speech_service.transcribe_audio` (Whisper `base`, local). Since all speech is English, we can also compare Whisper's English-only `base.en` model or force `language="en"`, a cheap accuracy gain we decide on here.
3. Computes **WER** (word error rate) against the script line (not for `_free` clips), giving a real STT metric per speaker, gender and environment.
4. Writes `manifests/audio.csv`: `audio_id, file, speaker, gender, record_id, env, duration_s, reference_text, whisper_transcript, whisper_language, wer`.

---

## 10. Step 7 — Split, validate, export 🤖 (lead runs)

**🤖 Claude builds** `tools/finalize_dataset.py`. It:
1. Merges all members' reviewed sheets → `manifests/complaints_reviewed.csv`.
2. Keeps the photo-grouped split from Step 3 (about 80% train / 20% test; text-only rows split by row; stratified so every category and severity is in the test set).
3. **Validates:**
   - every file referenced exists;
   - no duplicate texts;
   - category and severity values exactly match `config.py`;
   - the class-count minimums from §2 are met;
   - no `image_id` appears in both splits;
   - every test row is `human_verified` and cross-checked.
4. **Exports:**
   - `data/real/train.csv`: the Swap-Guide columns (`raw_complaint, category, severity, has_contradiction`) plus extra columns (`record_id, image_id, owner, variant, label_source`). Phase 7's `load_data` only reads the columns it needs, so the extras are harmless.
   - `data/real/test.csv`: same format, plus `image_file` and `audio_files` columns for multimodal evaluation.
5. Prints a **dataset card**: counts per category, severity, variant, split, owner and speaker; WER summary; inter-annotator κ; licence summary.
